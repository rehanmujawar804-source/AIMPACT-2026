# 03 — Scope & Acceptance Criteria

## MVP user flow
1. Select a supplied synthetic dispute case or paste a dispute message.
2. Load/choose the corresponding structured records.
3. Validate schemas and show any invalid rows.
4. Extract the claim into structured fields.
5. Match likely transaction records.
6. Run deterministic checks.
7. Show the evidence trace and findings.
8. Show unresolved questions and suggested verification steps.
9. Export/copy the investigation brief.

## P0 — required
- One dispute type: short delivery / quantity discrepancy.
- Stable record IDs.
- Structured synthetic data only.
- Deterministic arithmetic and validation.
- Source-linked findings.
- Explicit uncertainty states.
- Visible AI-extracted claim with editable fields or review step.
- At least 20 test cases; target 24–30 if time allows.
- Rules-only vs hybrid evaluation.
- One clean case, one discrepancy case, one ambiguous/missing-evidence case in the demo.
- Honest limitation statement.

## P1 — only if P0 is stable
- Simple Hinglish dispute wording if tested.
- Alternative candidate matches with confidence labels.
- Exportable JSON or downloadable report.
- Visual trace between claim, records, checks and findings.

## Out of scope for 8 hours
- OCR/PDF parsing of arbitrary documents.
- Production integrations or live customer data.
- Authentication, RBAC, multi-tenancy, payment processing.
- Automated email/WhatsApp responses.
- Legal advice, fraud verdicts, debt recovery.
- Blockchain, agents, voice, forecasting, embeddings/vector database unless a measured need emerges.
- Multi-dispute-type support.

## Acceptance criteria
A case is “demo-ready” only if:
- Every input row is schema-validated.
- Every computed amount/quantity is generated by deterministic code.
- Every factual finding includes valid source record IDs.
- An unresolved case does not get forced into a definitive answer.
- Missing data is described as missing from the provided dataset, not absent in reality.
- A clean case does not produce an unsupported discrepancy.
- The app does not claim fraud.
- A test suite covers the main status and arithmetic rules.
- The team can explain the AI contribution and show evaluation results.

## Definition of done for the vertical slice
Given a dispute message and the relevant records, a user can see:
- the extracted claim,
- the records selected,
- calculations,
- supported/conflicting/unresolved findings,
- source references,
- next verification step,
without needing to read raw model output.

## Failure handling
- Invalid schema: show row/field error; do not proceed silently.
- No candidate record: `NOT_FOUND_IN_PROVIDED_DATA`.
- Multiple plausible records: `UNRESOLVED` and show candidates.
- Contradictory records: `CONFLICTING_RECORDS`.
- Arithmetic mismatch: flag calculation with source IDs.
- LLM timeout/invalid JSON: retry once or fall back to manual claim fields; never invent a result.
